# Plan a portal task

Read AGENTS.md, all matching memory, the relevant product documents and open decisions. Inspect existing code before assuming a feature or endpoint exists.

1. Identify the exact scope and current approval state. Do not ask for permission already granted to that scope.
2. Use the 14 sections in plans/README.md. Name exact affected paths, real existing locators, proposed/confirmed/open contracts, measurable behavior, verification and rollback.
3. Keep proposed API/schema work reviewable rather than presenting it as an existing interface. Verify external provider contracts with official guidance.
4. Challenge the plan with at least three genuine rated objections, or two for a qualifying one-file change. Resolve them or state the precise blocking choice.
5. Isolate unresolved domains. Group necessary questions once; never turn an ambiguous yes into a business/security policy.
6. Present the plan path, readiness and objections. Seek Stephen's concrete scope approval only after the plan is ready.

Maintain plan history and source of approval. Do not write application code while only drafting the plan.
